## New command review and fixes (existing GATE-3..5)

[Redis source comparison](https://github.com/redis/redis/compare/8.2.1...8.10.3)
adds BLMOVEM, BACKUP, HIMPORT, HOTKEYS, TRIMSLOTS, AR* arrays, DELEX, DIGEST,
INCREX, LMOVEM, MSETEX, SDIFFCARD, SUNIONCARD, and stream extensions
(XCFGSET, XIDMPRECORD, XNACK and options). New data commands pass through;
backend version determines availability. Existing CLUSTER allowlists reject new
mutators such as MIGRATION and SYNCSLOTS. ARSCAN/ARGREP pair nesting is preserved.
SDK VECTOR.* and search helpers require matching backend capabilities and are
not asserted universally compatible by this suite.

The old gate returned `null` (allowed) for all five unsafe families below,
verified by importing `git show HEAD:src/commands.ts` in a scratch file and
calling `checkBlockedCommand`:

- `BLMOVEM src dst LEFT RIGHT 0`: blocks the shared connection indefinitely
  on empty source ([command source](https://github.com/redis/redis/blob/8.10.3/src/commands/blmovem.json)).
- `HIMPORT PREPARE fields name`: creates session-local fieldsets shared between
  independent HTTP callers ([source](https://github.com/redis/redis/blob/8.10.3/src/commands/himport-prepare.json)).
- `BACKUP START` and `TRIMSLOTS RANGES 1 0 16383`: server-wide backup and slot
  deletion operations ([BACKUP](https://github.com/redis/redis/blob/8.10.3/src/commands/backup-start.json),
  [TRIMSLOTS](https://github.com/redis/redis/blob/8.10.3/src/commands/trimslots.json)).
- `HOTKEYS START`: mutates server-wide tracking. Only HELP is allowed after upstream reconciliation;
  unknown subcommands fail closed.

Fix: `src/commands.ts:62`, `:77`, `:97`, and `:143` block session, blocking,
and server-wide commands (line references predate upstream integration). Unit tests and HTTP regressions cover single-command,
pipeline and transaction entry points. Pipeline command errors deliberately
remain HTTP 200 error slots; single-command and transaction reject with 400.
