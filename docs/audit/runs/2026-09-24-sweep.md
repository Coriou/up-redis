# Ecosystem sweep (Recipe 2): 2026-09-24

Base: `dd44f98cd09230bd31035b7c269d0dbf0366b46f` (main). This is the first sweep with a
report in `runs/`, so each upstream range starts at the version pinned at the base.
The same branch folds in open Dependabot PRs #27, #29, #30, #32 and #33, plus the newer
upstream patches, so dependency bumps and drift review merge together.

## 1. Bun runtime: 1.3.14 → 1.4.2

- 1.4.0 (2026-08-20) is a large release: the native code, including the RESP parser,
  was rewritten in Rust. The relevant changes:
  - Server error replies now reject with `ERR_REDIS_SERVER_ERROR`; the message text is
    unchanged. The proxy uses only `instanceof Error` and `.message`
    (`src/translate/transaction.ts`, `src/routes/command.ts`).
  - RESP3 big numbers now come back as a BigInt. `normalizeResp3` and `encodeResult`
    already turn BigInt into a string.
  - `RedisClient` `idleTimeout` now actually closes connections. The proxy never sets
    it on Redis clients (`src/redis.ts`).
  - `onclose` runs exactly once after a failure, which makes PubSub teardown more
    reliable.
  - A connection URL with an invalid db number now throws at startup instead of
    silently using db 0.
  - `Bun.serve` now cancels the response stream when the client aborts, which helps SSE.
  - `PSUBSCRIBE` is still missing from `RedisClient`, so `src/redis-pattern.ts` is
    still needed.
- Lockfile: Bun 1.4 keeps the version of an existing lockfile when it re-saves it.
  `bun.lock` is still `lockfileVersion: 1`, and Bun 1.3.6 installs it with
  `--frozen-lockfile`. If the lockfile is ever regenerated from scratch on 1.4 it
  becomes v2 and breaks the floor.
- Disposition: CI, `packageManager` and the Dockerfile are pinned to 1.4.2. The floor
  stays at 1.3.6, and the `runtime-floor` CI job and local runs below confirm it. No
  code change was needed.

## 2. Hono: 4.13.3 → 4.13.9

- 4.13.4: a listener passed to `onAbort` that throws no longer breaks `abort()`. This
  helps the SSE `stream.onAbort` calls.
- 4.13.5 and 4.13.7 are security releases. They fix `parseBody` form nesting, the cache
  middleware ignoring `#fragment` in query params, SSG and JSX streaming. The proxy uses
  none of these (`_token` is read with `c.req.query`).
- 4.13.8 and 4.13.9 fix Accept headers, the linear router, Lambda and JWT, none of which
  the proxy uses.
- Disposition: bumped. No other action.

## 3. Zod: 4.4.3 → 4.6.5

- Breaking-flagged changes: datetime values now need seconds, number and bigint formats
  are separated in the types, and optional/default resolution and `preprocess` typing
  changed. `src/config.ts` uses none of these.
- The config-shaped schema was run on both versions with these inputs: missing, `""`,
  `"  "`, `"0"`, `"abc"`, `" 8080 "`, `"1e3"` and `"TRUE"`. Results were identical.
- Disposition: bumped. No other action.

## 4. Redis and Valkey

| Line | Latest | Notes |
| --- | --- | --- |
| 6.2 | 6.2.24 | Security release (TLS use-after-free) |
| 7.4 | 7.4.11 | Security release |

New top-level commands since Redis 8.0, checked against the gate:

- `BLMOVEM` (8.10, flagged `blocking`): the gate allowed it. **GATE-3 (high)**, fixed.
  Reproduced on 8.10.2 before the fix: a bystander `PING` hung until an external
  `RPUSH`.
- `BACKUP` (8.10) and `HOTKEYS` (8.6): the gate allowed them. **GATE-4**, fixed with a
  `HELP`-only allowlist.
- `TRIMSLOTS` (8.4, `@dangerous`): the gate allowed it. **GATE-4**, fixed.
- `HIMPORT` (8.10, per-connection fieldsets): the gate allowed it. **GATE-5**, fixed.
- Already blocked:
  - `CLUSTER MIGRATION`, `SYNCSLOTS` and `SLOT-STATS`, through the CLUSTER allowlist.
  - Valkey 9.2 `ACL` role commands and `CONFIG INFO`.
- Data commands that need no action:
  - The 18-command `AR*` array family.
  - `DELEX`, `DIGEST`, `MSETEX`, `INCREX`, `LMOVEM` (non-blocking), `SDIFFCARD` and
    `SUNIONCARD`.
  - `XACKDEL`, `XDELEX`, `XNACK`, `XCFGSET` and `XIDMPRECORD`.
  - Valkey `HGETDEL` and `CLUSTERSCAN`.
- `XREADGROUP` gained `CLAIM`, `MAXCOUNT` and `MAXSIZE` in 8.4+. Redis requires an
  integer for every one of their values, so a crafted value cannot hide `BLOCK` from the
  gate. No action.
- Redis 6.2.23 fixed an RCE through a crafted stream `RESTORE` payload. This is recorded
  as **GATE-6 (low, open)**, a policy question.
- The Compose default digest moves from Redis 8.10.1 to 8.10.2. Dependabot never
  proposes this bump because of the `${VAR:-image}` interpolation (DEPLOY-8 note).

## 5. `@upstash/redis`: 1.38.2 → 1.39.0

- `http.ts`: `upstash-sync-token` is now set on the first request as well. The proxy
  emits `"0"` and ignores the request header. This is already tested.
- `http.ts`: a new `Upstash-Telemetry-Retry` header is sent on retried attempts. The
  proxy ignores unknown headers.
- Unchanged: error handling, the `Upstash-Encoding` and `Upstash-Response-Format` logic,
  pipeline and multi-exec handling, and subscribe/SSE parsing.
- New `AR*` helpers pass through, and their shapes are preserved by construction.
  Missing test coverage is recorded as **FIDELITY-5 (low, open)**.
- New `redis.vector` (`VECTOR.*`) namespace: this is Upstash-proprietary. The README now
  says it is unsupported and points to up-vector.
- Disposition: the pin is bumped to 1.39.0. No contract change for the proxy to match.
