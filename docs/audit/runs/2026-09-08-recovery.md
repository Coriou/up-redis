## Review findings and corrections

- The proposed stream gate still missed Redis's repeated/reordered GROUP syntax.
  The final parser skips opaque option arguments at every GROUP position. Tests
  cover blocked reads through single commands, pipelines, and transactions.
- The proposed ZMPOP flattening contradicted native RESP2. A disposable Redis 8
  `redis-cli -2 --json ZMPOP` probe and the
  [Redis command reference](https://redis.io/docs/latest/commands/zmpop/) show
  `[key, [[member, score], ...]]`. Preserve that nesting; the finding is refuted.
- JSON-valid PubSub payloads can contain physical formatting newlines. Remove
  CR/LF JSON whitespace while retaining numeric lexemes; escape non-JSON text.
  Exact and pattern events remain one SSE line. Real SDK coverage includes
  formatted JSON, newline strings, and ordered mixed payloads.
- Transaction timeout coverage originally stalled connection establishment,
  which already had a timeout. The new relay finishes HELLO before stalling
  MULTI, requires the exact timeout error, and verifies socket release and reuse.
- Subscriber cleanup closes the dedicated connection immediately instead of
  waiting for UNSUBSCRIBE. Setup has its own deadline. Stalled setup, disconnect,
  shutdown, and quiet subscription lifetimes are exercised over real sockets.
- The proposed release scan targeted an unpublished v-prefixed image tag and
  implicitly selected one architecture. The final workflow scans the immutable
  build digest separately for amd64/arm64, then promotes version/latest tags and
  creates the GitHub Release. The scanner version and actions are pinned.
- Compose forwards every documented app setting from `.env` or host variables.
  Schema coverage, external overrides, custom ports, and development loopback
  bindings are checked by `bun run check:compose` in test and release workflows.
- Requiring a newly introduced Redis password would break established upgrades.
  Authentication is available and recommended for new installations, while an
  unset password preserves boot compatibility. Default RDB persistence also
  stays unchanged. A compose-only AOF setting supports the explicitly staged
  migration in `docs/persistence.md`.
- The ignored local RDB was copied to owner-only storage outside the repository,
  checksum-verified, and removed from the worktree directory. No data was published.
